## 0. 方法论：三层归因，避免"自己给自己当裁判"

无法用人眼逐张看 50 张图，故把缠师原文定义固化为**独立参考判定器**（`.workbuddy/tmp/strict_reference.py`）——包含处理、分型、笔、中枢定理三、第20课 `[DD,GG]` 波动区间、第17课趋势链、第24课标准背驰，全部独立编码，**不 import 引擎任何 domain 代码**。

对照分三层，逐层隔离变量：

| 层 | A 组 | B 组 | 变量 |
|---|---|---|---|
| L1 笔 | 参考器自实现笔（老笔、分型间隔≥4） | czsc 库笔 | 笔构造算法 |
| L2 中枢 | 参考器 `build_zss` | 引擎 `build_zs_strict` | 中枢**边界判定**（同笔序列） |
| L3 买卖点 | 参考器严格判定器 | 引擎 `identify_bs_points` | 买卖点算法（同笔同中枢） |

关键：**L2/L3 必须在同一笔序列上做 A/B**，否则笔的差异会传导到中枢和买卖点，无法归因。

## 2. 差异根因：两类，其中一类是真 bug

### 根因 A：真 bug — `total_abs` 暖机兜底误触发（导致 S1/S2 漏报 2 对）

**样本**：300867 圣元环保 `S1 @2026-06-05`（上涨笔 `06-01~06-05`，H 22.38）

引擎拦截证据：

```
A: 2024-11-27~2024-12-10 dir=up H=14.72
C: 2026-06-01~2026-06-05 dir=up H=22.38
back: is_div=False area=1.16512->2.341944  DIF=0.1956->-0.0763  pass=['dif']
      mode=split→total_abs(暖机兜底)
```

逐层追溯：

1. 该上涨笔的 5 根 MACD 柱**全部为负**（`-0.78, -0.69, -0.50, -0.26, -0.11`）——零轴下方的反弹，多头力度尚未体现在柱上；
2. `calc_bi_macd_area` 的 `split` 模式对 `up` 笔只累加 `m.macd > 0` 的柱 → `has_value=False` → 返回 `None`；
3. 上轮为"分众 06-29 单根长下影"加的 `split → total_abs` 兜底把 `None` 解释为"短笔暖机数据不足"，用 `abs()` 重算 → 得到 **2.342**（负柱绝对和）；
4. 面积比较变成 `2.342 > 1.165` → 判"面积放大"，`AND` 逻辑下压掉了本该成立的 S1。

**这是语义错误**："上涨笔全程无正柱"是**真实的市场状态**（力度为零），不是"数据不足"。缠师第24课比较的是"同向趋势段的柱面积"，反向柱不代表该方向力度，应记作 0（参考器即如此：`0 < 1.165` → 面积背驰成立，S1 正确报出）。

**修复方案**（尚未落地，需确认）：区分"真暖机"与"合法零面积"——仅当 `macd_slice` 为空或全部 `m.macd is None` 时才触发 `total_abs` 兜底；若切片有值但同向柱为 0，直接返回 `0.0`，不兜底。需回归分众 06-29 案例确保不破坏原来的修复。

### 根因 B：口径差异 — `practical [ZD,ZG]` vs 严格 `[DD,GG]`（导致 B1/S1 多报）

**样本**：002393 力生制药 `B1 @2026-07-27`（引擎报、严格口径不报）

```
引擎 practical 链=2: [ZD 23.21~23.40, DD 18.63 GG 28.77]
                     [ZD 21.21~22.15, DD 19.68 GG 24.42]
引擎 strict    链=1
参考器 strict  链=1（两中枢 [DD,GG] 大幅重叠 → 扩展，非新生）
```

`practical` 用核心区间 `[ZD,ZG]` 判"依次下降"（23.21 > 21.21 → 成立）；严格第20课用波动区间 `[DD,GG]` 判，两中枢 `DD 18.63/19.68` 与 `GG 28.77/24.42` 大量重叠 → 属**中枢扩展（更高级别盘整）**，不构成趋势 → 不应有 B1。

**这不是 bug，是产品口径选择**：笔级近似下若严格用 `[DD,GG]`，趋势极稀少（参考器 50 只两年只报出 8 个 B1、0 个 S1 中的严格链场景），实战可用性差。`practical` 是有意的工程放宽。但必须**在输出中显式标注所用口径**，避免用户误以为这是缠师严格定义的结果。

### 已排除的怀疑

- **未来函数**：力生制药 practical 链的两个中枢 `edt=2025-10-16 / 2026-03-31` 均早于目标笔起点 `2026-07-06`，无未来数据。
- **三买三卖误报**：抽查的 B3/S3 位置条件（离开段破 ZG/ZD + 回试不回）全部严格成立，125 个 B3/S3 与参考器 100% 一致。
- **MACD 数值口径**：引擎预计算与参考器自算的 DIF 全序列极值完全一致（-1.0745 / 1.3787）。

## 3. 框架级优化经验（6 条）

1. **分层归因是审计的前提**。不拆笔/中枢/买卖点三层，"中枢数差 24%"会被误判成中枢算法 bug，实际是笔层传导。任何结构算法的对照审计都必须逐层固定下层变量。

2. **独立参考实现 > 人眼抽查**。把原文定义固化为不复用生产代码的可执行判定器，才能发现 `total_abs` 兜底这类"看起来合理、实际语义颠倒"的问题。人眼抽查 50 只不可能覆盖，且会被已知结论锚定。

3. **兜底逻辑是背驰判定的高危区**。把"数据缺失"与"合法的零值/反向值"混为一谈，会系统性反转判定方向。规则：兜底只在**数据真的不存在**（空切片/全 None）时触发；**值存在但符号相反**是市场事实，必须按其语义处理（记 0 或用有符号值），不能用 `abs()` 抹平。此原则应推广到 DEA、面积、力度等所有代理指标。

4. **口径即产品，必须显式化**。`practical` vs `strict`、`split` vs `total_abs`、老笔 vs 新笔，都是合法选择，但当前 API 只在请求参数里体现，输出的买卖点没有标注"在何种口径下成立"。建议在 `BsPoint` 增加 `definition_mode` 字段，前端展示"严格/实用"标签——这既是诚实性要求，也便于用户按口径筛选。

5. **笔构造是最大的系统性差异源（24%）**，且缠师原文未给出"独立 K 线数"的唯一数值。不应假装存在"唯一正确的笔"，而应在文档与输出中明确声明所用笔定义，并考虑把 `min_bi_len` 之外的分型间隔参数（老笔 4 / 新笔 3）暴露给用户。

6. **黄金样本要覆盖"反常"情形**。现有黄金快照（汇川/分众）都是"笔方向与柱方向一致"的常规案例，所以 `total_abs` 兜底 bug 一直没暴露。新增黄金样本必须包含：上涨笔零轴下反弹、下跌笔零轴上回调、单根长影线、缺口跳空等边界形态。

## 4. 禅师视角裁决与修复结果（2026-11-22 完成）

以缠师原文为准绳，三点均判定为必要，已全部落地：

| 决策点 | 禅师原文依据 | 裁决 | 落地 |
|---|---|---|---|
| ① 兜底误触发 | 第24课「比较下方对应的**绿柱子**和黄白线围成的面积……绿柱面积缩小表示背驰」——面积定义本身分方向；上涨笔全程绿柱时红柱面积=0 是真实测量值。拿反向柱绝对值冒充同向柱，等于用空头力度比较多头力度 | **必须修复** | `calc_bi_macd_area` 用 `has_data` 区分「数据全缺失」与「有柱但无同向柱」：前者返回 None 供兜底，后者返回 **0.0**。兜底注释同步更正 |
| ② practical 口径 | 第17课只要「依次上升/下降」；第20课 `[DD,GG]` 严格口径在笔级近似下让趋势绝迹。可允许笔级近似，但不可冒充原文严格口径 | **保留默认 + 必须标注** | `BsPoint`/`BsPointItem` 新增 `definition_mode` 字段：B1/B2/S1/S2 = `practical`，B3/S3 = `n/a`（只凭位置，与重叠口径无关） |
| ③ 黄金样本 | 既有快照全是「笔方向与柱同向」的常规形态，才漏掉此 bug | **必要** | 新增 `czsc_golden_syzb.json`（圣元环保 300867，上涨笔零轴下反弹）+ 2 条回归测试 |
